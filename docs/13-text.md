# 13 · 文字窗：文本流、控制码、排版

台词的正文不是纯字符串，而是一段**带控制码的字节流**。引擎在消息窗的每帧更新
`FUN_00418D40` 里逐字节解释它；本仓库对应 `rust/src/text.rs`。

## 1. 控制码

**小于 `0x14` 的字节是控制码**，其余都是 cp932 文字（cp932 的 ASCII 从 `0x20` 起，
双字节首字节从 `0x81` 起，所以不会撞车）。

| 码 | 参数 | 含义 | 处理函数 |
|---|---|---|---|
| `00` | — | 回车：x 回到左边距，y 不动 | 内联 |
| `01` | u8 索引 + B,G,R | 改颜色（0 正文 / 1 阴影 / 2 描边） | `FUN_0041BB80` |
| `02` | — | 等玩家点击（不换屏） | `FUN_00419640` |
| `03` | — | 清窗 / 回到顶部（新的一屏） | `FUN_00419690` |
| `04` | u8 | 单字节参数（语速之类） | `FUN_00419720` |
| `05` | — | 本条台词结束 | `FUN_0041C400` |
| `06` | — | **换行**：y += 行距 + 4，放不下就翻页等待 | `FUN_00419990` |
| `07` | u8 | 音效/其它 | `FUN_00431E50` |
| `08` | u32 | 长参数 | `FUN_00419A00` |
| `09` | u8 | 单字节参数 | `FUN_00419AF0` |
| `0A` | 3 字节 | ruby（注音） | `FUN_00419B50` |
| `13` | 名字串（≤28 字节，只留 13） | 说话人名 | 内联 `_strncpy` |
| `FF` | — | 进入绘制模式（后面才是正文） | 内联 |

### 实测分布（全篇 62,405 条 `0x2B`）

```
00  x188336   回车（其中 1311 条与 06 组成 CRLF）
06  x1311     换行
02  x32       等点击（翻页）
0a  x3        注音参数
04/01/0f/10/15  各 1~3 次
```

所以每句台词的结构就是：

```
00 03 FF <正文，换行写成 00 06> 00 00
 ↑  ↑  ↑                        └─ 结束
 │  │  └─ 进入绘制模式
 │  └─ 清窗（新的一屏）
 └─ 回车
```

## 2. 排版几何

| 项 | 值 | 出处 |
|---|---|---|
| 文字区左 / 上 | 16 / 16 | `+0x182C` / `+0x1830` |
| 文字区右 / 下 | 宽−16 / 高−16（552×152 → 536 / 136） | `+0x1834` / `+0x1838` |
| 行距 | 字高 + 4 = 20 | `FUN_00419990`：`y += [+0x38] + 4` |
| 字高 | 16（窗口基类默认，消息窗没改） | `FUN_0041B950`：`param_1[0xe] = 0x10` |
| 换行判定 | `y + 2 + 字高 < 下边界` 才放得下 | `FUN_00419990` |
| 折行判定 | `x + 字宽 > 右边界` 就换行 | `FUN_00418D40` 绘制循环 |
| 字形落点 | `(x, y + 2)` | `FUN_00419790` 调用处 |
| 字体 | `CreateFontA(0x14, 0,0,0, 900, …)`：高 20、字重 900 | `FUN_00416770` |
| 正文色 | `0xFFFFFF`（白） | `+0x3C` 默认值 |

按这套值，552×152 的窗口一行放得下 26 个全角字，最多 6 行（16/36/56/76/96/116）；
实测全篇单句最多 5 行。

## 3. 和阻塞的关系

`0x2B` 处理函数不调 `FUN_00434EB0`，所以脚本会一直挂在同一条指令上（见 `docs/11-engine.md`）。
真正解除挂起的是**文字窗自己**：文本流读完后走 `FUN_00434710`，进入等待点击状态；
玩家点一下，消息窗才回头把脚本放开。

文本流中间出现 `02` 时，会额外多等一次点击（同一屏继续写，不清窗）。

## 4. 本仓库的还原

`rust/src/text.rs`：

- `Metrics`：文字区几何（默认 552×152 → 16/16/536/136，行高 16）。
- `parse(raw, &Metrics, measure)`：把字节流解释成 `Layout { pages: Vec<Page>, name, colors, size, waits }`。
- `Page { rows: Vec<Row>, wait }`，`Row { y, x, text, glyphs }`，`Glyph { ch, x, y, size, color }`。
- `default_measure`：全角 = 字号、半角 = 字号/2（渲染时传真实字体度量）。

`kzn text` 可以直接看排版结果：

```
$ kzn text "$G" SNR01.ISF --lines 3
[001] 说话人 None 字号 20 屏 1 行 1 等待 1 颜色 FFFFFF/000000/000000
   p0 y=16  x=16  翌朝。
   p0 —— 等待点击
[002] 说话人 None 字号 20 屏 1 行 1 等待 1 颜色 FFFFFF/000000/000000
   p0 y=16  x=16  俺たち『四人』は食卓を囲んでいた。
   p0 —— 等待点击
共 3 句，等待 3 次，单句最多 1 行
```

`kzn shot` 现在直接按这套几何画字（字号 20、行距 20、左上角 = 窗框内 16,16）。

## 5. 还没做的

- `0x01` 改色：解析了，但渲染时每个字形都按正文色画（阴影/描边没画）。
- `0x0A` ruby（注音）：`FUN_0041B50` 的具体排版没解，全篇只 3 处。
- `0xD6` / `0x25`（画面写文本）走的是另一个类，几何还没对。
- `0xE0`~`0xE5` 文本对象：每个字有独立字号（默认 20）和颜色，用于标题/菜单。
