## 1. 为什么低频指令也必须做

按次数排，`0x05/0x44/0xF4/0x2B/0x78/0x3A` 六条就占了 96%。但剩下 68 条几乎全是**功能入口**：

- `0x70/0x71/0x72` → BGM / SE 播放，只有 61 次，却是全部声音；
- `0x20/0x21/0x23/0x30/0x40/0x48/0xA0/0xA1/0xA5/0xA6` → **只在 `START.ISF` 出现**，也就是存档/读档/设置菜单；
- `0x74/0x75/0x76/0x7B` → 选项分支，决定路线；
- `0xE0`~`0xE5` → 文字窗口外观（位置/颜色/字体），不还原就永远长得不像原版。

所以「按次数优化」的思路是错的，必须逐条啃。

## 3. 解一条指令的标准流程

1. 从 `DAT_004359e4[op]` 拿跳表项，取该条目第一个 `call` 的目标（本表第 3 列）；
2. `analyze_function` 反编译，重点看 `vm+0x1C`（指令基址）与返回值：
   - 返回 0 → 主循环把 `pc` 推到指令尾（普通指令）；
   - 返回 1 → 处理函数自己改了 `pc`（跳转类）；
3. 用 `/tmp/inv2.py` 的载荷直方图确认字段宽度（长度恒定的按定长解，变长的找结尾 `\0` 或计数前缀）；
4. 在 `tools/isf_vm.py` 与 `rust/src/isf.rs` **同时**实现，跑 `kzn dump --steps 200000` 对 41 个脚本做逐字节 diff；
5. 不一致就说明语义错了——这是最硬的回归测试。
