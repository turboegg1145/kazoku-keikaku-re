# 07 · 0x37 系统功能（FUN_004378F0）

`0x37 <功能号> <参数>` 全作出现 399 次。两个操作数在引擎里都被截成 **字节**
（`FUN_00434990` 取出的 32 位值直接赋给 `byte`），所以有效范围是 0..255。

## 1. 参数上限（越界直接忽略）

```c
if ((kind < 0x14) && arg_ok) return 1;   // 什么都不做
```

其中 `arg_ok` 是「参数是否超出上限」：

| 功能号 | 参数上限 |
|---|---|
| `0x00` `0x01` `0x08` | < 3 |
| `0x02`..`0x07`、`0x09`..`0x0D`、`0x0F`..`0x11`、`0x13` | < 2 |
| `0x0E` | < 4 |
| 其他 | 不检查 |

也就是说**越界的调用会被静默丢弃**，不是报错。

## 2. 全局开关表

这些字节都住在 `0x4891B8..0x4891EE` 和 `0x4892E4/E5`，另外 `engine+0x801` 也在其中。
实现里统一用「地址低 12 位」当下标（`0xB8`、`0x2E4`、`0x801`），Rust 和 Python 用同一套编号。

| 功能号 | 参数 | 写入 | 含义 |
|---|---|---|---|
| `0x00` | 0 | `BC=C0=C4=1` | 左/右/中键全部有效 |
| `0x00` | 1 | `BC=1 C0=1 C4=0`，再按 `B8` 走一段分支 | 「只留左键」，并且可能把 `B8`（跳过/自动）打开 |
| `0x00` | 2 | `BC=C0=C4=0` | 三个键全禁 |
| `0x01` | 0/1 | 改 `D4`（点击边沿）、`B8` | 鼠标点击的「刚按下」标志 |
| `0x02` | 0/1 | `C8 = (arg==0)` | 某类输入锁 |
| `0x03` | 0 | `D8=CC=1`，否则清 0 | 条件成立才置位 |
| `0x04` | 0 | `DC=D0=1`，否则清 0 | 同上 |
| `0x05` | 0 | `E0 = (arg==0)` | |
| `0x06` | 0 | `CC = B8 && D8` | |
| `0x07` | 0 | `D0 = D4 && DC` | |
| `0x08` | 0 | `vm+0x549=1`，清 `vm+0x54D` 的 bit1，**停语音声道 0x20** | 关掉「跳过」 |
| `0x08` | 1 | `vm+0x549=0` | 开「跳过」 |
| `0x08` | 2 | `vm+0x549=1`，清 bit1 | 同 0 但不停语音 |
| `0x09` | 0/1 | `E4 = (arg==0)` | |
| `0x0A` | 0/1 | `E8 = (arg!=0)` | **出现 401 次，最常用**：点击穿透/吞掉这一下 |
| `0x0C` | 0/1 | `vm+0x54A = arg` | 0x3A 的 `sid=0x0C` 直接读它 |
| `0x0D` | 0/1 | 只切窗口激活状态 | 无画面意义 |
| `0x0E` | 0..3 | `vm+0x54D = arg`；`arg&2` 时同时清 `vm+0x549` | 0x3A 的 `sid=0x0E` 读它 |
| `0x0F` | 0/1 | `engine+0x801 = (arg!=0)` | 0x3A 的 `sid=0x0F` 读它 |
| `0x10` | 0/1 | `vm+0x54B = (arg!=0)` | |
| `0x11` | 0/1 | `EC = (arg!=0)` + 窗口标志 | 文字绘制的「记住笔位」 |
| `0x13` | 0/1 | `2E5 = (arg!=0)` | 文字绘制模式位 |
| `0x15` | 0/1 | `ED = (arg!=0)` | |
| `0x16` | 0/1 | `2E4 = (arg!=0)` | 文字绘制模式位 |
| `0x17` | 任意 | `EE = arg` | |

`bVar1`（引擎里 `0x81C != 0 && *(0x81C+0x134) != 0`）表示**音频对象已就绪**，
我们的实现里恒为真（`SysFlags::audio_ready`）。

## 3. 为什么必须真的改这些字节

`0x3A`（SYSIF）就是读它们来跳转的：

| `sid` | 读 |
|---|---|
| `0x00` | `AC` |
| `0x01` | `D4`、`B8` |
| `0x02`..`0x07` | `C8`/`D8`/`DC`/`E0`/`CC`/`D0` |
| `0x08` | `vm+0x54C`，否则 `vm+0x549` |
| `0x0B` | `A1` |
| `0x0C` | `vm+0x54A` |
| `0x0E` | `vm+0x54D`（`54E==1 && 54C==0` 时或上 2） |
| `0x0F` | `engine+0x801` |

所以 `0x37` 写、`0x3A` 读，是一个闭环：只记录事件而不改字节，会让剧本走进错误分支。
这一版实装后，`dump` 出来的台词数和之前不同（分支真的变了），属于预期。

## 4. 事件

`kzn dump` 里仍然输出 `[SYSFUNC] kind=.. arg=..`，方便和 Python 侧逐行对拍。
