# 文件格式

本文只记录**已实测通过**的结论。没验证的会明确标成"推测/未解"。

---

## 1. 归档容器 SM2MPX10

所有大文件（`GGD` `ISF` `SE` `VOICE1` `VOICE2` `WMSC` `DATA` `GGD2`）都是同一种容器。

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 8 | 魔数 `SM2MPX10` |
| 0x08 | u32 | 条目数 |
| 0x0C | u32 | 目录区大小（本作未使用，目录固定从 0x20 开始） |
| 0x10 | 12 | 归档内部名（NUL 填充） |
| 0x1C | u32 | 常量 `0x20` |
| 0x20 | 20×N | 目录项 |

目录项：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 12 | 文件名，cp932，NUL 填充（8.3 风格，如 `SNR00.ISF`） |
| 0x0C | u32 | 数据偏移（绝对） |
| 0x10 | u32 | 数据长度 |

实测 8 个归档全部解析成功，**0 个越界条目**：

| 归档 | 条目数 | 大小 |
|---|---|---|
| GGD | 842 | 338,847,472 |
| ISF | 41 | 5,903,312 |
| SE | 136 | 5,324,080 |
| VOICE1 | 11,215 | 217,815,376 |
| VOICE2 | 11,081 | 206,041,504 |
| WMSC | 27 | 63,941,920 |
| DATA | 26 | 1,757,072 |
| GGD2 | 137 | 15,031,344 |

> 注意：网上流传的格式说明里有"目录偏移由头部给出 / 目录项 24 字节"的版本，与本作不符。本作目录固定 `0x20` 起、每项 20 字节。

工具：`tools/sm2mpx.py`

## 2. ISF 脚本

41 个文件，是**编译后的字节码**，不是文本。要过两层解密。

### 2.1 第一层：SECRETFILTER100a 异或壳

- 先丢掉文件末尾 16 字节（长度/校验尾巴）。
- 密钥不是常量：从 `KIZUNAR.EXE` 里那张 2048 字节的 `UOB0...` 表实时算出来（本作位于**文件偏移 0x74218**）。
- 算法：
  - 密钥长度 = `str2hex(encode_hex(secret[0x500+i] - secret[0x100+i]))`（i=0,1）
  - 密钥字节 = `encode_hex(secret[0x510+i] - secret[0x110+i])`
  - 每 klen 字节换一次密钥：`key[i] = encode_hex(key[i] + secret[(index & 0x3F)*0x10 + i])`
  - 全程用一张 36 字符表 `G5FXIL094MPRKWCJ3OEBVA7HQ2SU8Y6TZ1ND` 做"数字→字母"编码

### 2.2 第二层：ikuar_decrypt

按 `data[4:6]` 的版本魔数，对 offset 8 之后的全部字节做变换：

| 魔数 | 变换 |
|---|---|
| `0x9795` | 每字节循环右移 2 位 |
| `0xD197` | 每字节按位取反 |
| `0xCE89` | 每字节异或 `data[6]` |

本作 41 个文件全部是 `0x9795`。

### 2.3 解密后的布局

```
u32 head_len
u32 version (0x9795)
(head_len-8)/4 个 u32 偏移表   ← 全部落在文件内、数值各异，确认是有效表
head_len 起：指令流
```

例：`SNR00.ISF` head_len = 13288，偏移表 3320 项；`TCG.ISF` head_len = 32，偏移表 6 项。

### 2.4 指令流编码

```
opcode(u8) + len(u8) [+ ext]
len < 0x80  → 头部 2 字节，payload = len-2
len == 0x80 → 头部 3 字节，第 3 字节是长度
len == 0x81 → 头部 3 字节，第 3 字节 + 0x100
len 含头部自身
```

用这个规则切分，**41 个文件全部恰好切到文件末尾，无一失败**。总计 551,127 条指令、93 种 opcode。

### 2.5 已确认的指令

| opcode | 语义 | 证据 |
|---|---|---|
| `0x2B` | **文本** | payload `00 03` + 说话人 + `FF` + cp932 正文；全作 62,298 条 |
| `0x78` | 语音文件名 | payload 为 ASCII，如 `ONK0001` |
| `0xF0` | 语音所在归档 | payload 如 `\x04VOICE2` |
| `0x56` | 图像资源名 | payload 如 `EFEC01.GG2` |
| `0x02` | 子脚本/模块名 | `BGMLOAD` `SELOAD` |
| `0xF4` | 压入布尔常量 | 长度恒为 3，payload 只有 `00`/`01` |
| `0x05` | 带 u16 操作数（**未确认**） | 长度恒为 4，数值集中在 3218–3319，与文本交替出现 |

### 2.6 文本编码（0x2B 详解）

```
00 03 ff <cp932 文本> 00 00 00        叙述
00 03 04 <u8 说话人> ff <cp932 文本>   对白
```

- `0x00 0x06` = 句中换行
- `0x00 0x00` = 文本结束
- 其余 `< 0x20` 的字节是控制码（如 `0x02` 清窗口），显示时应丢弃

实测：`SNR00.ISF` 3141 条文本，其中 3080 条带语音文件名，语音与文本一一对应。全作共 62,298 条。

工具：`tools/isf_crypto.py`、`tools/isf_text.py`

## 3. 图像 GGD / GG2

**未完全解决**（这是目前唯一的大缺口）。

### 3.1 GGD（背景 / 立绘 / 按钮）

**头部只有 8 字节**，0x08 起直接是像素数据：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 4 | 魔数 `b9 aa b3 b3` |
| 0x04 | u16 | 宽 |
| 0x06 | u16 | 高 |
| 0x08 | ... | 像素流 |

**未压缩像素格式（已用汉化补丁的 `ggd_sc/` 验证并成功渲染）：**

- 24bpp **BGR**（用 RGB 看会得到紫皮肤）
- 行字节数 = **(文件大小 - 8) / 高**，行尾可能有 0/1/2 字节填充
  - `CG2_BAO.ggd`：640×480，923048 B → 行 1923 B（=3×641）
  - `MODORU.ggd`：96×96，27752 B → 行 289 B（=3×96+1）
  - `CG2_DGB.ggd`：384×156，180032 B → 行 1154 B（=3×384+2）
- 所以**不要**用 `3*宽` 当步长，必须用 `(size-8)/h`

渲染结果：`CG2_BAO.ggd` 是一张 640×480 的 CG（人物+背景），`MODORU.ggd` 是 96×96 的
三态「返回」按钮（普通/悬停/按下各 32 行）。

**压缩流（原版文件）——token 表基本验证完，只剩 `00` 的一个变体：**

行结构：**每行 1 个控制字节 + 变长 token 流**，解出 `w` 个像素后进入下一行。
控制字节含义未知（观察值 0x05 / 0x0a / 0x22，行间会变）。

"距离" 指**解码缓冲区里往回数的像素数**，可以跨行（第 1 行开头就会引用第 0 行）。

| 形态 | 长度 | 语义 | 验证状态 |
|---|---|---|---|
| `00 <n> <x>` | 3 | 重复上一个像素 `n` 次 | 已验证（含 `n=103` 的长重复） |
| `01 <x> <d>` | 3 | 从距离 `d` 复制 **2** 个像素 | 已验证（`01 02 15` → 距离 21，两个像素都逐字节吻合） |
| `03 <d> <x>` | 3 | 从距离 `d` 复制 **1** 个像素 | 已验证（十余处逐字节吻合） |
| `<d> <x>` | 2 | 短形式：从距离 `d` 复制 1 个像素，`4 ≤ d < 0x20` | 已验证（`0b 05` → 距离 11，`13 06` → 距离 19） |
| `02 <d> <x>` | 3 | 未定（疑似复制 2 个像素，距离在第 2 字节） | 未定 |
| 其它 | 3 | 字面像素（BGR 三字节，原样） | 已验证 |

注意 `01` 的距离在**第 3 字节**、`03` 的距离在**第 2 字节**；另一个字节是随颜色变化的
校验/索引值（同一颜色总是同一个值），解码时用不到。

**唯一卡点：** `CG2_BAO.GGD` 第 0 行第 22 像素处出现 `00 02 05`，但目标色不是"上一个像素"，
而是一个更早的颜色，且重复了 **3** 次而不是 2 次。同一行前 21 个像素、20 多个 token 全部逐字节正确，
所以不是对齐问题，而是 `00` 还有第三种变体没识别。解决这一条就能解出整张图。

**验证方法（可复现）：** 汉化补丁的 30 个 `ggd_sc/*.ggd` 与原归档里的同名文件是同一张图
（首行 18 字节在 923048 字节的补丁图里**只出现一次**，位置正是第 0 行），前者未压缩、后者压缩。
`tools/ggd_stream.py` 可以逐 token 打印解码结果，直接和补丁图对比。

**未压缩图（补丁）的行结构：** 每行同样是 `1 字节前缀 + w*3 像素`，行尾再补 0–2 字节，
所以步长必须用 `(文件大小-8)/高`，像素从 `0x09` 开始。

### 3.2 GG2 / GG0（事件 CG、窗口素材）

魔数是 ASCII `GGA00000`，注意**扩展名不可靠**：`2CH_OF02.GG0` 里装的其实是 GG2 格式。

```
0x00  8   "GGA00000"
0x08  u16 宽
0x0A  u16 高
0x0C  ... 未知
```

### 3.3 已排除的可能

- 不是裸 24bpp/16bpp（扫描 offset 0–63、stride 96×1..4，相邻像素相关性全部等于随机值）
- 不是单纯 RLE（多种 (计数,值) 组合都只吃掉文件的一小部分）
- 不是 12 种常见参数的 LZSS
- 不是整段异或（不同文件头部 20 字节高度相似，说明没加密）

### 3.4 已知线索

- 压缩流里大量出现 3 字节记录 `[03|04] [u16]` 与 `00 01 xx`，控制字节（< 0x08）占全流 26%–34%
- 数据段里能直接看到平滑的 24bpp 像素三元组（相邻像素每通道差 1–6），说明**至少部分是明文像素**
- 解码器**不在** GGD 类的虚函数里（对象 0x1858 字节，vtable 只有 3 槽，全是析构/通用文件打开），
  也不是以魔数或 `word[+4]`/`word[+6]` 读取开头的函数——按字符串、魔数、指令形状搜过两轮都定位不到，
  详见 `notes/negative-results.md`
- 因此下一步建议换路线：**把原版引擎当预言机**（Wine 跑起来后截图，或在 `CreateDIBSection` 返回的
  缓冲区下断点 dump），842 张图可以批量拿到，不必解开压缩算法

## 4. 音频 / 视频

- 语音、音效、BGM：**OGG Vorbis**（`OggS` 魔数），直接可播
- 视频：**MPEG-1**（`FAM_OP.MPG` 28MB、`FAM_OPHQ.MPG` 97MB、`DOLOGO.MPG`）
- `WMSC` 归档里是 Windows Media 相关资源，本作未见播放路径
