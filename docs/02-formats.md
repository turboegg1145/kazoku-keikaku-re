# 文件格式

本文只记录**已实测通过**的结论。没验证的会明确标成"推测/未解"。

---

## 1. 归档容器 SM2MPX10

所有大文件（`GGD` `ISF` `SE` `VOICE1` `VOICE2` `WMSC` `DATA` `GGD2`）都是同一种容器。

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 8 | 魔数 `SM2MPX10` |
| 0x08 | u32 | 条目数 |
| 0x0C | u32 | 目录区大小（本作未使用，目录固定从 0x20 开始） |
| 0x10 | 12 | 归档内部名（NUL 填充） |
| 0x1C | u32 | 常量 `0x20` |
| 0x20 | 20×N | 目录项 |

目录项：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 12 | 文件名，cp932，NUL 填充（8.3 风格，如 `SNR00.ISF`） |
| 0x0C | u32 | 数据偏移（绝对） |
| 0x10 | u32 | 数据长度 |

实测 8 个归档全部解析成功，**0 个越界条目**：

| 归档 | 条目数 | 大小 |
|---|---|---|
| GGD | 842 | 338,847,472 |
| ISF | 41 | 5,903,312 |
| SE | 136 | 5,324,080 |
| VOICE1 | 11,215 | 217,815,376 |
| VOICE2 | 11,081 | 206,041,504 |
| WMSC | 27 | 63,941,920 |
| DATA | 26 | 1,757,072 |
| GGD2 | 137 | 15,031,344 |

> 注意：网上流传的格式说明里有"目录偏移由头部给出 / 目录项 24 字节"的版本，与本作不符。本作目录固定 `0x20` 起、每项 20 字节。

工具：`tools/sm2mpx.py`

## 2. ISF 脚本

41 个文件，是**编译后的字节码**，不是文本。要过两层解密。

### 2.1 第一层：SECRETFILTER100a 异或壳

- 先丢掉文件末尾 16 字节（长度/校验尾巴）。
- 密钥不是常量：从 `KIZUNAR.EXE` 里那张 2048 字节的 `UOB0...` 表实时算出来（本作位于**文件偏移 0x74218**）。
- 算法：
  - 密钥长度 = `str2hex(encode_hex(secret[0x500+i] - secret[0x100+i]))`（i=0,1）
  - 密钥字节 = `encode_hex(secret[0x510+i] - secret[0x110+i])`
  - 每 klen 字节换一次密钥：`key[i] = encode_hex(key[i] + secret[(index & 0x3F)*0x10 + i])`
  - 全程用一张 36 字符表 `G5FXIL094MPRKWCJ3OEBVA7HQ2SU8Y6TZ1ND` 做"数字→字母"编码

### 2.2 第二层：ikuar_decrypt

按 `data[4:6]` 的版本魔数，对 offset 8 之后的全部字节做变换：

| 魔数 | 变换 |
|---|---|
| `0x9795` | 每字节循环右移 2 位 |
| `0xD197` | 每字节按位取反 |
| `0xCE89` | 每字节异或 `data[6]` |

本作 41 个文件全部是 `0x9795`。

### 2.3 解密后的布局

```
u32 head_len
u32 version (0x9795)
(head_len-8)/4 个 u32 偏移表   ← 全部落在文件内、数值各异，确认是有效表
head_len 起：指令流
```

例：`SNR00.ISF` head_len = 13288，偏移表 3320 项；`TCG.ISF` head_len = 32，偏移表 6 项。

### 2.4 指令流编码

```
opcode(u8) + len(u8) [+ ext]
len < 0x80  → 头部 2 字节，payload = len-2
len == 0x80 → 头部 3 字节，第 3 字节是长度
len == 0x81 → 头部 3 字节，第 3 字节 + 0x100
len 含头部自身
```

用这个规则切分，**41 个文件全部恰好切到文件末尾，无一失败**。总计 551,127 条指令、93 种 opcode。

### 2.5 已确认的指令

| opcode | 语义 | 证据 |
|---|---|---|
| `0x2B` | **文本** | payload `00 03` + 说话人 + `FF` + cp932 正文；全作 62,298 条 |
| `0x78` | 语音文件名 | payload 为 ASCII，如 `ONK0001` |
| `0xF0` | 语音所在归档 | payload 如 `\x04VOICE2` |
| `0x56` | 图像资源名 | payload 如 `EFEC01.GG2` |
| `0x02` | 子脚本/模块名 | `BGMLOAD` `SELOAD` |
| `0xF4` | 压入布尔常量 | 长度恒为 3，payload 只有 `00`/`01` |
| `0x05` | 带 u16 操作数（**未确认**） | 长度恒为 4，数值集中在 3218–3319，与文本交替出现 |

### 2.6 文本编码（0x2B 详解）

```
00 03 ff <cp932 文本> 00 00 00        叙述
00 03 04 <u8 说话人> ff <cp932 文本>   对白
```

- `0x00 0x06` = 句中换行
- `0x00 0x00` = 文本结束
- 其余 `< 0x20` 的字节是控制码（如 `0x02` 清窗口），显示时应丢弃

实测：`SNR00.ISF` 3141 条文本，其中 3080 条带语音文件名，语音与文本一一对应。全作共 62,298 条。

工具：`tools/isf_crypto.py`、`tools/isf_text.py`

## 3. 图像 GGD / GG2

**未完全解决**（这是目前唯一的大缺口）。

### 3.1 GGD（背景 / 立绘 / 按钮）

```
0x00  4  魔数 b9 aa b3 b3
0x04  u16 宽
0x06  u16 高
0x08  u8  位深/格式（实测 0x05）
0x09  3   未知（各文件不同，疑似校验或调色板种子）
0x0C  1   0x00
0x0D  ... 压缩数据
```

例：`MODORU.GGD` 96×96、20264 字节；`2AO_OF01.GGD` 432×336、294710 字节。

### 3.2 GG2 / GG0（事件 CG、窗口素材）

魔数是 ASCII `GGA00000`，注意**扩展名不可靠**：`2CH_OF02.GG0` 里装的其实是 GG2 格式。

```
0x00  8   "GGA00000"
0x08  u16 宽
0x0A  u16 高
0x0C  ... 未知
```

### 3.3 已排除的可能

- 不是裸 24bpp/16bpp（扫描 offset 0–63、stride 96×1..4，相邻像素相关性全部等于随机值）
- 不是单纯 RLE（多种 (计数,值) 组合都只吃掉文件的一小部分）
- 不是 12 种常见参数的 LZSS
- 不是整段异或（不同文件头部 20 字节高度相似，说明没加密）

### 3.4 已知线索

- 压缩流里大量出现 3 字节记录 `[03|04] [u16]` 与 `00 01 xx`，控制字节（< 0x08）占全流 26%–34%
- 数据段里能直接看到平滑的 24bpp 像素三元组（相邻像素每通道差 1–6），说明**至少部分是明文像素**
- 下一步应直接在 `KIZUNAR.EXE` 里定位解码器：从脚本 `0x56`（图像资源名）的 VM 处理函数往下追，而不是继续盲猜

## 4. 音频 / 视频

- 语音、音效、BGM：**OGG Vorbis**（`OggS` 魔数），直接可播
- 视频：**MPEG-1**（`FAM_OP.MPG` 28MB、`FAM_OPHQ.MPG` 97MB、`DOLOGO.MPG`）
- `WMSC` 归档里是 Windows Media 相关资源，本作未见播放路径

## 5. 存档 KIZUNAR.SAV

2319 字节，明文但字段未解析。已知：

- `0x66` 起有一段 u32 序列：`78 00 00 00 c0 00 00 00 08 09 00 00 00 02 00 00 04 00 00 00`
- `0x140` 处 `05 00 00 00`，之后是 `0xFF` 填充

对一个重写版来说存档格式可以自己定，不影响移植。
