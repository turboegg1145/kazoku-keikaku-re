# 文件格式

本文只记录**已实测通过**的结论。没验证的会明确标成"推测/未解"。

---

## 1. 归档容器 SM2MPX10

所有大文件（`GGD` `ISF` `SE` `VOICE1` `VOICE2` `WMSC` `DATA` `GGD2`）都是同一种容器。

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 8 | 魔数 `SM2MPX10` |
| 0x08 | u32 | 条目数 |
| 0x0C | u32 | 目录区大小（本作未使用，目录固定从 0x20 开始） |
| 0x10 | 12 | 归档内部名（NUL 填充） |
| 0x1C | u32 | 常量 `0x20` |
| 0x20 | 20×N | 目录项 |

目录项：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0x00 | 12 | 文件名，cp932，NUL 填充（8.3 风格，如 `SNR00.ISF`） |
| 0x0C | u32 | 数据偏移（绝对） |
| 0x10 | u32 | 数据长度 |

实测 8 个归档全部解析成功，**0 个越界条目**：

| 归档 | 条目数 | 大小 |
|---|---|---|
| GGD | 842 | 338,847,472 |
| ISF | 41 | 5,903,312 |
| SE | 136 | 5,324,080 |
| VOICE1 | 11,215 | 217,815,376 |
| VOICE2 | 11,081 | 206,041,504 |
| WMSC | 27 | 63,941,920 |
| DATA | 26 | 1,757,072 |
| GGD2 | 137 | 15,031,344 |

> 注意：网上流传的格式说明里有"目录偏移由头部给出 / 目录项 24 字节"的版本，与本作不符。本作目录固定 `0x20` 起、每项 20 字节。

工具：`tools/sm2mpx.py`

## 2. ISF 脚本

41 个文件，是**编译后的字节码**，不是文本。要过两层解密。

### 2.1 第一层：SECRETFILTER100a 异或壳

- 先丢掉文件末尾 16 字节（长度/校验尾巴）。
- 密钥不是常量：从 `KIZUNAR.EXE` 里那张 2048 字节的 `UOB0...` 表实时算出来（本作位于**文件偏移 0x74218**）。
- 算法：
  - 密钥长度 = `str2hex(encode_hex(secret[0x500+i] - secret[0x100+i]))`（i=0,1）
  - 密钥字节 = `encode_hex(secret[0x510+i] - secret[0x110+i])`
  - 每 klen 字节换一次密钥：`key[i] = encode_hex(key[i] + secret[(index & 0x3F)*0x10 + i])`
  - 全程用一张 36 字符表 `G5FXIL094MPRKWCJ3OEBVA7HQ2SU8Y6TZ1ND` 做"数字→字母"编码

### 2.2 第二层：ikuar_decrypt

按 `data[4:6]` 的版本魔数，对 offset 8 之后的全部字节做变换：

| 魔数 | 变换 |
|---|---|
| `0x9795` | 每字节循环右移 2 位 |
| `0xD197` | 每字节按位取反 |
| `0xCE89` | 每字节异或 `data[6]` |

本作 41 个文件全部是 `0x9795`。

### 2.3 解密后的布局

```
u32 head_len
u32 version (0x9795)
(head_len-8)/4 个 u32 偏移表   ← 全部落在文件内、数值各异，确认是有效表
head_len 起：指令流
```

例：`SNR00.ISF` head_len = 13288，偏移表 3320 项；`TCG.ISF` head_len = 32，偏移表 6 项。

### 2.4 指令流编码

```
opcode(u8) + len(u8) [+ ext]
len < 0x80  → 头部 2 字节，payload = len-2
len == 0x80 → 头部 3 字节，第 3 字节是长度
len == 0x81 → 头部 3 字节，第 3 字节 + 0x100
len 含头部自身
```

用这个规则切分，**41 个文件全部恰好切到文件末尾，无一失败**。总计 551,127 条指令、93 种 opcode。

### 2.5 已确认的指令

| opcode | 语义 | 证据 |
|---|---|---|
| `0x2B` | **文本** | payload `00 03` + 说话人 + `FF` + cp932 正文；全作 62,298 条 |
| `0x78` | 语音文件名 | payload 为 ASCII，如 `ONK0001` |
| `0xF0` | 语音所在归档 | payload 如 `\x04VOICE2` |
| `0x56` | 图像资源名 | payload 如 `EFEC01.GG2` |
| `0x02` | 子脚本/模块名 | `BGMLOAD` `SELOAD` |
| `0xF4` | 压入布尔常量 | 长度恒为 3，payload 只有 `00`/`01` |
| `0x05` | 带 u16 操作数（**未确认**） | 长度恒为 4，数值集中在 3218–3319，与文本交替出现 |

### 2.6 文本编码（0x2B 详解）

```
00 03 ff <cp932 文本> 00 00 00        叙述
00 03 04 <u8 说话人> ff <cp932 文本>   对白
```

- `0x00 0x06` = 句中换行
- `0x00 0x00` = 文本结束
- 其余 `< 0x20` 的字节是控制码（如 `0x02` 清窗口），显示时应丢弃

实测：`SNR00.ISF` 3141 条文本，其中 3080 条带语音文件名，语音与文本一一对应。全作共 62,298 条。

工具：`tools/isf_crypto.py`、`tools/isf_text.py`

## 3. 图像 GGD / GG2

### 3.1 GGD —— 已完全解开 ✅

解码器是 **`FUN_0040b190`（0x40b190–0x40b396）**，签名
`undefined4 FUN_0040b190(char *dst, int *reader, int nbytes)`。下面的操作码表是
从它的反编译结果**抄下来的**，不是猜的。50 个 `.GGD` 成员全部**精确消耗到最后一个字节**
并精确产出 `w*h` 像素。

**两族头部**（扩展名不可靠，按魔数判断）：

| 族 | 魔数 | 宽 | 高 | 流起点 |
|---|---|---|---|---|
| A `GGD` | `b9 aa b3 b3` | u16 @0x04 | u16 @0x06 | **0x08** |
| B `GGA` | `"GGA00000"` | u16 @0x08 | u16 @0x0A | **0x0C** |

**流是扁平的操作码表**，没有行偏移表、没有分块头、没有「上一个距离」状态。
解满 `w*h` 个像素就停（最后一个 token 可以越过末尾）。

| 操作码 | 参数 | 长度 | 语义 |
|---|---|---|---|
| `00` | `<k>` | 2 | 重复上一个像素 `k` 次 |
| `01` | `<k> <d8>` | 3 | 从距离 `d` 复制 `k` 个像素 |
| `02` | `<k> <d16>` | 4 | 从距离 `d` 复制 `k` 个像素（**16 位距离**）|
| `03` | `<d8>` | 2 | 从距离 `d` 复制 1 个像素 |
| `04` | `<d16>` | 3 | 从距离 `d` 复制 1 个像素（**16 位距离**）|
| `05`–`FF` | — | `1+3*(b-4)` | 原始像素段，长度 = `b-4` |

- 像素 3 字节，**BGR** 顺序。
- 距离以**像素**计：源偏移 `(pos - d) * 3`。距离**可以跨行**——这正是 `02`/`04`
  存在的理由：640 宽的图往回一行是 640 像素，一个字节装不下。
- `05`–`FF` 一条能装 1–251 个原始像素，所以 `0xFF` = 251 个原始像素。
- 距离为 0 或大于当前位置都算非法，没有特例。

**这解释了汉化补丁的「填充字节」**：`ggd_sc/*.ggd` 不是「每 251 像素插一个填充字节」，
而是**每 251 像素写一个 `0xFF` 原始段头**。`0xFF` = 251+4，`0x8E` = 138+4（640 宽一行的
最后一段），`0x64` = 96+4（96 宽整行一段）。之前两天的「行步长 = (size-8)/h」只是这个结构的副作用。

**校验结果**（30 个 `ggd_sc` 补丁 vs 归档内压缩图，逐字节）：

| 图 | 尺寸 | 流消耗 | 像素差异 |
|---|---|---|---|
| CG2_BAO | 640×480 | 709622/709622 | 3576 px (1.2%)，首差 r10 c221 |
| CG2_BCH | 640×480 | 746911/746911 | 3727 px |
| EYE01 | 640×480 | 623246/623246 | 8754 px |
| MODORU | 96×96 | 20264/20264 | 4127 px，但**全是 ±1**（抖动） |

差异集中在**补丁重绘过的文字区域**，其余像素逐字节相同——补丁图是重新渲染/重新量化的，
不能当逐字节基准，只能当「结构 + 近似」基准。判断解码是否正确的硬标准是
**流是否精确消耗完 + 像素数是否精确**。

**未压缩补丁的写法**（`tools/ggd.py:encode_raw` 会生成同样结构）：每行按 251 像素切段，
每段一个 `n+4` 头字节后跟 `n` 个原始像素。

### 3.2 GG2 / GG0（事件 CG、窗口素材）—— 未解

魔数 `GGA00000`，`w@0x08` `h@0x0A`，但 `0x0C` 起的流**不是** GGD 那套操作码：
792 个成员全部在第一个 token 就撞上「位置 0 重复上一个像素」，说明是另一种容器
（疑似分页/分块，见 `0x0C` 处的 `00 00 20 10` 与成串的 `30 00 00 00` 块头）。

### 3.3 已排除的可能

见 `notes/negative-results.md`（十余条被否证的假设 + EXE 定位弯路）。


## 4. 音频 / 视频

- 语音、音效、BGM：**OGG Vorbis**（`OggS` 魔数），直接可播
- 视频：**MPEG-1**（`FAM_OP.MPG` 28MB、`FAM_OPHQ.MPG` 97MB、`DOLOGO.MPG`）
- `WMSC` 归档里是 Windows Media 相关资源，本作未见播放路径

## 6. 汉化补丁

- `kzn_sc.exe` + `kzn_sc.dll`（dwing 加壳，节名 `dwing0/1/2`）+ `isf_sc.bin` + `ggd_sc/`
- 不改原文件，运行时替换文本；`kzn_sc.ini` 里 `COMPANY=DO` / `KEY=KIZUNAR` / `WEIGHT=400`
- 对重写版没影响：直接读原版 ISF 即可，中文可以用自己的翻译表
