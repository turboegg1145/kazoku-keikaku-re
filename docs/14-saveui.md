# 14 · 存读档界面

原版的存读档**不是脚本**，是 Win32 对话框。这一节记录对话框资源、存档格的真实写入顺序，
以及移植版怎么重画。

## 1. 界面在哪儿

`.rsrc` 里有 40 多个 DIALOG 模板（引擎是通用的 Ikura GDL，塞了别的游戏留下的），
本作用到的是：

| ID | 尺寸(DLU) | 标题 | 控件 |
|---|---|---|---|
| 182 | 237×173 | `   Load   ` | 10 行「データN + 作成日　----年 --月 --日　--時 --分」+ 10 个行框 |
| 183 | 236×163 | `   Load   ` | 同上 + 右侧 140×120 预览控件 |
| 195 | 310×159 | `   Load   ` | 更宽的版本（36 个控件）|

控件坐标（DLU，`x` 按 `*6/4`、`y` 按 `*13/8` 换算成像素）：

```
データ1      ( 10,  10)  55×10
データ2      ( 10,  26)  55×10      ← 每行 +16
…
作成日标签    ( 70,  10) 160×10      ← 和 データN 同一行
行框          (  0,   2) 237×21      ← 每行 +16，样式 0x50000007 = GROUPBOX
```

也就是说列表是**纯文字**（编号 + 日期），缩略图只画在右边**当前选中**那一格（183 的 140×120 控件）。

## 2. 存档格写入顺序（`FUN_00426EA3`）

`[dialog+0x5FC] == 2` 走存档，否则走读档。存档分支：

```
1. GetLocalTime(engine + 0x76C + slot*0x10)        // 27 个 SYSTEMTIME 缓存
   write 16 字节
2. FUN_00426790(engine, &ptr, buf, 0xE128)         // 截当前画面 → 160×120 24bpp
   成功 write 0xE128 字节，失败 seek 0xE128
3. FUN_004346F0(engine+0x818, engine+0x85C+slot*0xA0)   // 取出缓存的日期串
   write 0xA0 字节（cp932）
4. for i in 0..5 { write u32 0 }                    // 5 个空的扩展段
5. FUN_00423DA0(vm_bitarray, archive)               // 位数组，ceil(n/8) 字节
6. FUN_00424C80(vm_vars, archive)                   // 变量数组，n*4 字节
7. write 0x30 个 0                                   // 尾部填充
8. 拷贝剩下的块；表里块 29（已读位图）按需追加
9. DeleteFileA + MoveFileA（SAVE.TMP → 正式文件）
```

**注意第 4 步和第 7 步：扩展段和尾部全是 0，没有剧本位置。**
这条结论把「读档回到存档那一行」这条路堵死了 —— 原版就是只恢复位数组和变量数组。
（`0x48` 建块、`0x49/0x4A` 每句读写旗标，才是这个游戏的进度模型；标题画面靠
块 27 里的旗标决定能进哪一章，见 `TITLE.ISF` 的 `0x07 SWITCH` 跳转表。）

## 3. 日期字符串

列表里那行字是：

```c
sprintf(buf, "%4d/%2d/%2d %02d:%02d", st.wYear, st.wMonth, st.wDay, st.wHour, st.wMinute);
```

格式串在 `0x47EE98`（`"%s/%s/%s %s:%s"`），中间几段分别用 `0x47EEB4`(`%4d`)、
`0x47EEB0`(`%2d`)、`0x47EEA8`(`%02d`) 先格式化。所以实际文本是 `2026/10/23 22:31`。
空格未使用的格子显示 `0x47EE84` 那串占位符。

## 4. 移植版实现（`rust/src/saveui.rs`）

```
SaveScreen {
    mode: Save | Load,
    page: 0..2, cursor: 0..8,        // 27 格 = 3 页 × 9 格
    file: SaveFile,                  // 和 sav.rs 同一套解析/打包
    path: "<游戏目录>/KIZUNAR.SAV",
    message: String,                 // 底部提示
}
```

- 布局：面板 528×408 居中；9 行 300×30、行距 34；右侧 160×120 预览；底部翻页 + 确定/取消；
- `hit(x, y)` 做命中测试，返回 `Hover / Pick / Prev / Next / Ok / Cancel`；
- `save()` 依次写 SYSTEMTIME、缩略图、日期串、5 个空扩展段、位数组、变量数组、0x30 尾部；
- `load()` 调 `Vm::apply_slot` 恢复位数组和变量数组；
- `flush()` 写 `SAVE.TMP` 再换名，和原版一致。

命令行验证：

```
kzn save <游戏目录> -o /tmp/s.png --put 4
# 写入 データ5 -> /tmp/s.sav（62500 字节）
#   回读：日期 2026/10/23 21:32，位数组 129 字节，变量 542 个
#   逐字节回环：一致
```

62500 = 120（块表）+ 60181（格）+ 72（块 27）+ 2120（块 28）+ 7（块 29），和 PC 版存档结构完全一致。

## 5. 还没做的

- 原版用 `FUN_00426790` 截画面，我们直接缩当前帧（差别只在过渡中的一帧）；
- 原版列表可以滚动/翻页（`[dialog+0x600]` 是每页格数），我们固定 3 页；
- 确认框、覆盖提示、失败时的 MessageBox 文本（`0x47F4C4` 附近那串）没做；
- 存档格的「拡張段」目前恒为 0，和原版一致；将来若要存剧本位置，得另开一份 sidecar。
